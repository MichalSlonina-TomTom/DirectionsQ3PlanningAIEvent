# Key findings — Refining features with Claude

Plain-language summary of the web research (full report: [`../research/refining-features-with-claude.md`](../research/refining-features-with-claude.md)).
Ranked by how much each should shape the talk. Each row links to its primary source.

| # | Finding | What it means for the talk | In plain terms | Source |
|---|---|---|---|---|
| 1 | **The context window fills fast and quality degrades as it fills.** Nearly every technique is downstream of managing that budget. | Use as the talk's organizing spine — explain *why* each technique exists. | Claude has a limited "working memory." Stuff too much in and it gets sloppy — like a desk too cluttered to find anything. Most tricks just keep that desk tidy. | [Claude Code best practices](https://code.claude.com/docs/en/best-practices) |
| 2 | **Give Claude a check it can run** (tests / build / linter / diff / screenshot). The single highest-leverage practice. | The Verify phase is the whole game. | Give Claude a way to mark its own homework — a test that passes or fails. Without one, "it looks done" is all you've got. | [Claude Code best practices](https://code.claude.com/docs/en/best-practices) |
| 3 | **Verify in a fresh, independent context** — the agent that wrote the code shouldn't grade it. | Demoable: an adversarial reviewer that sees only the diff + criteria. | Don't let the person who wrote the essay also grade it. Open a clean session to check the work with fresh eyes. | [Claude Code best practices](https://code.claude.com/docs/en/best-practices) |
| 4 | **Separate research/planning from implementation** — Explore → Plan → Code → Commit. | Maps onto your Pick→Research→Plan→Build loop. | Look before you leap. If Claude starts typing code immediately, it often solves the wrong problem. Understand first, plan second, build third. | [Claude Code best practices](https://code.claude.com/docs/en/best-practices) |
| 5 | **Treat Claude as a fast, fallible junior, not a one-shot oracle.** First attempts are often mostly throwaway. | Reframes iteration as the method, not failure. | It's a brilliant but green intern, not a genie. The first draft is rarely right — that's normal. You go back and forth. | [Sanity: first attempt will be 95% garbage](https://www.sanity.io/blog/first-attempt-will-be-95-garbage) |
| 6 | **The role shift is measured.** Feature work rose 14.3%→36.9% of usage; PRs/engineer/day +67%; one engineer "70%+ shifted to reviewer." | A strong opening stat. | Your job changes from *writing* code to *checking and steering* it — more editor, less typist. And the numbers show it really happens. | [Anthropic: how AI is transforming work at Anthropic](https://www.anthropic.com/research/how-ai-is-transforming-work-at-anthropic) |
| 7 | **Prompt engineering / meta-prompting is supported with first-party tools.** But auto-generated prompts carry outdated patterns. | Confirms technique (a) — feature with the caveat. | You can ask Claude to help write the instructions you give Claude. Handy — but double-check them, because some tools still suggest old tricks that now backfire. | [Anthropic prompt improver](https://claude.com/blog/prompt-improver) |
| 8 | **Data-mining works via search-then-fetch over MCP + subagents, with a human gate.** ADR/architecture extraction is draft-only. | Confirms technique (b). Caveat: stale wikis cause "context rot." | Claude can go read your Jira, Confluence, code, and Slack to gather background — but feed it the *right* pages, not everything, and never trust old wiki pages blindly. | [Anthropic: effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) |
| 9 | **Delegate investigation to subagents that return short summaries.** | The fix for "infinite exploration." | Send a helper off to read 100 files and come back with a one-paragraph answer — so your main conversation doesn't drown in detail. | [Claude Code best practices](https://code.claude.com/docs/en/best-practices) |
| 10 | **Capture the plan/spec as a durable, version-controlled artifact**; execute in a fresh session. | The spec is the shared context. | Write the plan down in a file in the repo, not in the chat. Then everyone (and the next session) works from the same agreed plan. | [Spec-driven development with Claude Code](https://alexop.dev/posts/spec-driven-development-claude-code-in-action/) |
| 11 | **Multi-agent is a poor fit for most *coding*.** Great for research, but burns ~15× tokens and runs out of memory. | Don't oversell parallelism for Build. | Running a swarm of agents to *build* one feature usually backfires — they trip over each other and cost a fortune. Great for research, not the actual coding. | [Anthropic: building a multi-agent research system](https://www.anthropic.com/engineering/built-multi-agent-research-system) |
| 12 | **Bloated `CLAUDE.md` is self-defeating** — too long and Claude ignores it. | Also: Claude Code doesn't auto-read `AGENTS.md` (import via `@AGENTS.md`). | The instructions file you give Claude should be short. Pile on too many rules and it starts ignoring all of them — like fine print nobody reads. | [Claude Code memory docs](https://code.claude.com/docs/en/memory) |
| 13 | **Don't always pay plan-mode ceremony:** "If you could describe the diff in one sentence, skip the plan." | Nuance for the Pick phase. | Don't bother with a big plan for a tiny change. Save the ceremony for the work that's actually complicated. | [Plan mode in Claude Code](https://codewithmukesh.com/blog/plan-mode-claude-code/) |

## Honest conflicts worth a slide of their own

- **Who owns planning?** Anthropic *reserves* high-level design for humans (planning only grew 1%→9.9%), while Sanity / incident.io push Claude into drafting specs. ([Anthropic research](https://www.anthropic.com/research/how-ai-is-transforming-work-at-anthropic))
- **Does spec ceremony beat plain plan mode?** HN skeptics: "a detailed-enough spec is just code you can't run." ([best practices](https://code.claude.com/docs/en/best-practices))
- **"Single-file-change" rules are now outdated** and block coordinated cross-file edits. ([large codebases](https://claude.com/blog/how-claude-code-works-in-large-codebases-best-practices-and-where-to-start))
